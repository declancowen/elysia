# Native CLI compatibility history

Elysia installs and updates the company CLI separately from the app. An app release does not pin every user to one CLI version. The provider snapshot reports the managed CLI version; record that version when testing a release.

The historical entries below come from published GitHub release commits. The CLI baseline is the version declared by the regression fixture, not a captured native installation. Native package versions and checksums were not recorded for these releases, so native compatibility must not be inferred from the fixture version alone.

## CLI 0.3.9 review

Release notes and the native 0.3.9 ZIP supplied by the maintainer on 2026-10-08. Package SHA-256: `56027c720207be2707129a7941040da344a8d938417d7ef0f6720005db993631`. The supplied setup implementation was exercised on macOS in temporary managed profiles. Gateway/CA requests, the update download and Claude marketplace commands used controlled substitutes; no live search, routed delegation, company authentication, or Windows runtime was tested. This establishes setup integration, not live-service certification.

| Change                                                          | Integration status                                                                                                                                                                                                                                                                                  |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--compression-stats --json`                                    | The protected host path accepts this exact command; the regression fixture checks argument forwarding and rejects unrelated flags and shell chaining.                                                                                                                                               |
| Tavily MCP registration during `--init`/`--update`              | Supplied native setup verified on initialization, update re-execution, adoption and existing-profile migration. The user MCP entry carries the native gateway header in the managed profile; global MCP configuration is not imported.                                                              |
| Automatic shunt plugin installation                             | Supplied native installer exercised through initialization, update, adoption and migration with controlled marketplace responses. Adoption backfills missing native routing values and preserves custom values and tracing privacy preferences. Live private-marketplace access remains unverified. |
| Compression slash command delegates to the CLI                  | Managed `elysia-*` commands remain native-owned and are not overwritten by global extension synchronization.                                                                                                                                                                                        |
| Shared plugin installer, proxy timeout and no credential prompt | Supplied source confirms the shared installer and 60-second marketplace-add timeout; controlled execution verifies managed user scope and `GIT_TERMINAL_PROMPT=0`. Live marketplace latency/authentication remains unverified.                                                                      |
| Linux/WSL CA environment fix                                    | Native-owned. This fork ships macOS and Windows desktop installers; WSL connections remain disabled. No Linux/WSL runtime test was performed.                                                                                                                                                       |

The app uses its managed CLI copy, so updating the global CLI alone does not update app sessions. Use the Elysia provider updater in Settings to run native `--update` against the managed profile. After setup successfully publishes a new configuration version, an existing thread resumes its native conversation with a fresh Claude process on the next user turn, loading updated user settings, MCP configuration and plugins. Background continuations keep their live process; new user turns that would replace running background work require it to finish or be stopped first. Focused adapter tests cover reuse, resume and this safety guard. Failed post-update child processes do not publish a new configuration version or report success.

Existing app profiles without a recorded configuration version receive native addon setup once during their usual startup validation. This uses their existing credentials without a new gateway authentication request. CLI 0.3.8 profiles remain supported; they skip addon helpers absent from that version.

Working credentials do not establish feature compatibility. For each new CLI release, check its feature setup separately on initialization, managed update and existing-sign-in adoption, then exercise the feature in a new and an existing thread. Do not copy unrelated global MCP configuration or guess native private setup helpers to fill an unverified adoption gap.

## Recording the next release

Before publishing, append the app release and source commit, resolved SDK version, actual managed CLI version tested, native package checksum if available, platforms tested, and the result. Record initialization, update and existing-sign-in adoption separately when the CLI changes setup behavior. Use “Not verified” for missing evidence; keep fixture coverage separate from native tests. Never record credentials, environment dumps or authenticated download URLs.
